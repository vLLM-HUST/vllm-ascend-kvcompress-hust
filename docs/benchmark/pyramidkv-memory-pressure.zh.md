# PyramidKV 固定预算内存压力规程

[English](pyramidkv-memory-pressure.md) | 简体中文

这是针对 PyramidKV issue #1 的独立探索场景，承接[元数据净成本规程](pyramidkv-net-cost.zh.md)，
检验回收请求占用的 KV 块能否在较紧预算下带来服务收益。不替换原 8 GiB 系列，也不证明最大容量。

开测前只固定一个预算：原生 OFF 和 PyramidKV ON 都为**每 worker 2 GiB KV**。保留既定
Qwen3.5-35B-A3B BF16/TP2、910B2、32768 上下文、4 序列、4096 批量 token、MTP2、APC、
异步调度、FULL_AND_PIECEWISE、1368/beta-2 方法及选中页物化。两臂冻结相同的显式批量元数据
源码和开关。不修改选择或生成参数，不搜索有利预算；启动或请求失败就停下调查，不改成 eager，
也不悄悄降低上下文限制。

采用 OFF/ON/ON/OFF 四次全新进程，沿用 8 GiB 系列保存的 137 个合成输入与 12 个 QA 冒烟输入，
保留预定义的 38 个合成排除项、99 个计量请求和相同分组。合成输入长为 1024/8192/24576，
并发 1/4，每格三批，固定生成 128 token。不同请求使用唯一 API cache salt，跨进程复用完全相同
输入 ID 和盐。抢占可能造成同一请求重算，因此保留并报告缓存 token 计数，不强制恢复后仍为零。
如果出现非零值，必须检查重算路径，不得宣称全程无缓存。

预登记的主比较是 **24576 输入 token／并发 4**，使用总输出 token 除以批次总耗时。必须报告全部
六格及各进程/批次值、TTFT、TPOT、E2E、失败、抢占和 MTP 接受计数差、实际采样 HBM 与 KV
池使用率，不事后挑最好的一格。此预算受限场景的收益不能外推成 8 GiB 下的收益、相同预留下的
设备 HBM 节省、SLO 保证或最大并发能力。负结果同样保留。

核对调度器事务与两路 TP 确认。压力运行中，抢占可能为同一个 API 请求产生多个事务生命周期；
应保留并检查全部事务，不强制恰好一次，也不删除重复项。每次提交都须语义/物理长度匹配且两路
worker 确认，并解释额外重算。原始 SSE、服务日志、指标、进程/源码身份、启动记录与完整合同归入
benchmark。12 个 QA 样例只作冒烟，原 300 例质量评测单独保留。正式请求期间不得并行运行测试、
lint、分词或数据审计。
