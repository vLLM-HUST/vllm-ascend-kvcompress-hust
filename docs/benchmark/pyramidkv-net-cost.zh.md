# PyramidKV 元数据与服务净成本规程

[English](pyramidkv-net-cost.md) | 简体中文

本独立实验规程回应 [PyramidKV #1](https://github.com/vLLM-HUST/vllm-ascend-pyramidkv-hust/issues/1)，
不替代 Frontier SWE/AgentX 合同，也不构成公开 wheel 验收。此前 selected-page 算子改善不能证明服务加速。

每轮事前固定模型、tokenizer、宿主、源码摘要及实际 910B2 设备。沿用合格的 Qwen3.5-35B-A3B
BF16/TP2 实验宿主、FULL_AND_PIECEWISE、MTP2、APC、异步调度、32768 上下文、四序列、
4096 批处理 token 和每 worker 8 GiB KV；保留 1368/beta-2 算法及压缩阈值。
这不是官方 v0.18 baseline。

## 诊断

分别计时宿主元数据构造和调度压缩，不插入设备同步，保留调用及请求 ID。
时长包含宿主派发及隐式同步，不能称为独立 NPU 算子时间；插桩服务时延仅供诊断。
先做两个 8192-token warmup，再各做两个 1024/8192/24576-token 独立输入、128 固定输出、
并发一的请求。候选插桩诊断可复用输入，但不能代替无插桩服务比较。

## 无插桩服务比较

采用四次独立进程，顺序 OFF/ON/ON/OFF。两臂源码相同，仅切换压缩激活；OFF 是原生服务，
不故意加入昂贵的空压缩路径。旧 ON 记录属于另一种比较；本系列无计时装饰器。

复用既有 selected-page 的固定合成输入：1024/8192/24576 输入、128 固定输出、并发 1/4，
每格三组；并发一每组三请求，并发四每组八请求。每个合成请求设置独立 API `cache_salt`，跨进程复用同一 token ID 和盐，
出现 cached prompt token 则拒绝验收。保留事前排除的 33 个 warmup 和五个重复性探针：
每进程 137 个合成请求，其中 99 个参与性能统计。

报告累计输出 token/组耗时、每进程/每组结果、TTFT、端到端时延、TPOT、失败、抢占、
观测 HBM 和 KV 使用。核对原始 SSE、usage、结果、源码/输入摘要及 ON 的 scheduler/双 TP
确认，OFF 不得出现压缩提交。组内重复不能冒充独立进程，C4 成功不能证明最大容量，
释放 KV 所有权不能冒充 HBM 降低。测量期间不运行测试、lint、分词或数据审计。

## 正确性与边界

保留每个 LongBench 任务原开发集前四题，共 12 题 smoke；提示、生成预算和原 QA-F1 不改。
原实现 ON 诊断与候选 ON 输出可检查有限的元数据回归边界，不替代既有 300 题质量评估，
也不支持新的任务质量声明。不按结果调整选择或排除失败。

传输优化必须保持修正值、各层长度、语义位置、私有写入位置、MTP 拒绝草稿及图补齐语义。
CPU 回归及真实输出/事务核对必要，服务系列决定压缩是否有净收益。负结果及混合结果均须保留。
原始证据、分析和确切实验合同统一发布到 `vllm-hust-benchmark`。

## 显式开启的批量元数据候选

`VLLM_ASCEND_KVCOMPRESS_BATCHED_METADATA=1` 将逐层长度和写入槽操作合并成二维
张量，默认仍关闭。实现只适用于单 CP、连续的展开逻辑块表、匹配的物理/逻辑块
几何以及共享的基础序列元数据；其他形状沿用原生逐层路径。持久化槽位行保持图
捕获地址，图桶中未使用的槽位重置为 `-1`。

服务试验前，用固定宿主实际的 NPU 块表原生算子逐项核对候选槽位，覆盖混合压缩/
未压缩请求、请求行重排、不等查询数、多个展开物理页、填充及推测回滚。CPU/NPU
合成对照只证明整数元数据等价，仍需实际 FULL_AND_PIECEWISE/MTP2 服务冒烟。
两臂冻结同一开关和独立源码快照；保留先前候选的完整结果，包括负结果。不得将
不同实现的 OFF/ON 测量拼接为配对比较。

已验证的构建器把序列长度放在 CPU，写入槽位放在 NPU。批量长度运算遵循实际
元数据设备，每次调用产生独立存储，保留先前尚在执行的长度视图；只有写入槽位
地址跨调用保持稳定。
